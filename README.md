# User Service

The **User Service** is the identity and authentication backbone of the e-commerce platform. It handles user registration, JWT-based login, Two-Factor Authentication (2FA) via OTP, password recovery, real-time WebSocket notifications, and transactional email delivery for order confirmations and system alerts.

---

## Features

- **User Registration & Login**: Secure registration with field-level validation (email uniqueness, password strength) and stateless JWT-based authentication.
- **JWT Token Issuance**: Generates signed JWT tokens (HMAC-SHA, 1-hour expiry) consumed by all downstream microservices for authorization.
- **Two-Factor Authentication (2FA)**: Opt-in OTP-based 2FA — generates a time-limited OTP, sends it via email, and validates before issuing the JWT.
- **Password Recovery**: Forgotten-password flow that sends an OTP to the registered email; verifies and resets the password.
- **Toggle 2FA**: Allows authenticated users to enable or disable 2FA for their account.
- **User Profile Lookup**: Retrieve public user profile information by user ID (used by other microservices via Feign).
- **Email Notifications**: Sends transactional HTML emails (order confirmations, OTPs, alerts) using Spring Mail over SMTP (Office 365).
- **Email with Attachments**: Supports sending emails with file attachments (e.g., PDF invoices generated by Order Service).
- **RabbitMQ Consumer**: Listens for asynchronous events published by Order Service (e.g., order confirmation events) and triggers corresponding email notifications.
- **WebSocket Support**: Provides real-time push notification channels to connected frontend clients via STOMP over WebSocket.
- **Distributed Tracing**: Integrated with Zipkin via Micrometer Brave for cross-service request tracing.

## Configuration

The service runs on port **`8086`** and fetches its full configuration from the centralized Spring Cloud Config Server.

### Key Properties (`user-service.properties` in Config Server):

| Property | Default Value | Description |
| :--- | :--- | :--- |
| `spring.datasource.url` | `jdbc:mysql://localhost:3307/EcommerceDB` | MySQL database URL |
| `spring.datasource.username` | `root` | MySQL username |
| `spring.datasource.password` | `root123` | MySQL password |
| `jwt.secret` | `myVeryStrongSecretKey...` | HMAC key used to sign/verify JWTs |
| `jwt.expiration` | `3600000` | JWT validity in milliseconds (1 hour) |
| `spring.rabbitmq.host` | `localhost` | RabbitMQ host |
| `spring.rabbitmq.port` | `5672` | RabbitMQ port |
| `spring.rabbitmq.username` | `guest` | RabbitMQ username |
| `spring.rabbitmq.password` | `guest` | RabbitMQ password |
| `spring.mail.host` | `smtp.office365.com` | SMTP mail server host |
| `spring.mail.port` | `587` | SMTP port (STARTTLS) |
| `spring.mail.username` | `<configured email>` | Sender email address |
| `spring.mail.password` | `<configured password>` | Sender email password |
| `spring.mail.from` | `<configured email>` | From address in sent emails |

## REST API Documentation

### 1. Authentication Endpoints (`/api/auth`)

| Method | Path | Auth Required | Description |
| :--- | :--- | :---: | :--- |
| **POST** | `/api/auth/register` | ✗ | Register a new user account with name, email, password, and role. |
| **POST** | `/api/auth/login` | ✗ | Authenticate credentials and receive a JWT (or OTP challenge if 2FA is enabled). |
| **POST** | `/api/auth/verify-otp` | ✗ | Submit the OTP received via email to complete login or password reset. |
| **POST** | `/api/auth/toggle-2fa` | ✓ | Enable or disable Two-Factor Authentication for the authenticated user. |
| **POST** | `/api/auth/forgot-password` | ✗ | Initiate the password recovery flow — sends a reset OTP to the registered email. |
| **GET** | `/api/auth/user/{userId}` | ✓ | Retrieve a user's public profile information by their numeric ID. |

### 2. Notification Endpoints (`/api/auth/notifications`)

| Method | Path | Auth Required | Description |
| :--- | :--- | :---: | :--- |
| **POST** | `/api/auth/notifications/send` | ✓ | Send a plain-text or HTML email notification to a specified recipient. |
| **POST** | `/api/auth/notifications/send-with-attachment` | ✓ | Send an email with a file attachment (e.g., a PDF invoice). |

## Data Model

### `users` table (MySQL)

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `BIGINT` | PK, Auto-increment | Unique user identifier |
| `name` | `VARCHAR` | NOT NULL | User's full name |
| `email` | `VARCHAR` | UNIQUE, NOT NULL | User's email address |
| `password` | `VARCHAR` | NOT NULL | BCrypt-hashed password |
| `role` | `VARCHAR` | — | Role: `CUSTOMER`, `SELLER`, or `ADMIN` |
| `is_2fa_enabled` | `BOOLEAN` | Default `false` | Whether 2FA is active |
| `current_otp` | `VARCHAR` | — | Active OTP (cleared after verification) |
| `otp_expiry` | `DATETIME` | — | OTP expiration timestamp |

## Build, Test, and Run

### 1. Compile and Package
```bash
./mvnw clean package
```
> Tests are skipped by default (`skipTests=true` in `pom.xml`).

### 2. Run Tests
```bash
./mvnw test -DskipTests=false
```
> Runs 48 unit tests covering auth service, JWT utilities, notification logic, and security config.

### 3. Run Locally
```bash
./mvnw spring-boot:run
```
> Ensure the following services are running before starting:
> - Config Server (`8888`)
> - Eureka Server (`8761`)
> - MySQL (`3307`)
> - RabbitMQ (`5672`)

### 4. Build Docker Image
```bash
docker build -t user-service .
```
> The `Dockerfile` uses `eclipse-temurin:17-jre-alpine` and copies the pre-built JAR from `target/`.

### 5. Run via Docker Compose
```bash
docker compose up user-service
```
> Refer to the root `docker-compose.yml` for the full environment variable configuration.

## CI/CD

The GitHub Actions workflow at [`.github/workflows/ci-cd.yml`](.github/workflows/ci-cd.yml) automatically:
1. Checks out the code.
2. Sets up JDK 17 (Temurin) with Maven dependency caching.
3. Builds and tests the service with `./mvnw clean package -DskipTests=false`.
4. Builds and pushes the Docker image to **GitHub Container Registry (GHCR)** on every push to `main`, `master`, or `develop`.
